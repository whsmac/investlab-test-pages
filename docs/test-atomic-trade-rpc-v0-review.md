# TEST 원자적 거래 RPC v0 — 검토 및 시험 계획

상태: **설계 코드만 작성, 미설치, 미실행**. 기존 개인 테이블 v2 자체도 미설치 상태.

## 구현 후보
- 함수 `investlab_post_trade_v0`: USD 결제 매수/매도만 허용
- 인증된 사용자 ID 확인, 계좌 소유권 확인, 계좌 행 잠금
- 같은 계좌/요청 ID의 중복 요청은 동일 거래라면 기존 거래 ID 반환
- 같은 요청 ID에 다른 매매 내용을 보내면 오류
- USD 현금 부족 매수 및 주식 수량 부족 매도 거부
- 거래 헤더 1개 + 주식/현금 leg 2개를 하나의 함수 트랜잭션에서 기록
- 오류 발생 시 함수가 포함된 SQL 트랜잭션 전체 롤백

## 보안상 아직 적용 금지인 이유
- SECURITY DEFINER 함수의 소유자 권한과 EXECUTE 권한, search_path, RLS 우회 위험을 검증해야 함
- 직접 INSERT/UPDATE/DELETE 경로가 열려 있으면 계좌 잠금/무결성 검사를 우회할 수 있음
- 계좌별 잠금이 유효하려면 **모든** 거래 변경이 동일한 잠금 규칙을 지켜야 함
- 동일 request_id가 서로 다른 계좌에 쓰이는 것을 전역 차단할지 정책 확정 필요
- 수수료, 환전, 기초 잔고, 배당, 취득원가, 원화 세금, 소수점 정밀도 정책 미구현
- 사후 정정/역거래, 거래 발생일 순서에 따른 과거 잔고 음수 검사 미구현
- 실제 테스트 사용자 A/B 및 anon에 대한 PostgREST RPC 호출 검증 미완료
- v2 테이블 및 이 함수는 설치 승인 전까지 **실행 금지**

## 필수 검증 시나리오
| 사례 | 기대 결과 |
|---|---|
| A의 계좌에 A가 매수 | 현금 부족 시 거부, 충분할 때 이벤트+2 legs |
| A가 B의 계좌로 매수 | 거부 |
| 비로그인 RPC 호출 | 거부 |
| 동일 요청 ID·동일 내용 2회 | 이벤트 1개 |
| 동일 요청 ID·내용 변경 | 오류 |
| 현금 부족 매수 | 전체 롤백 |
| 주식 부족 매도 | 전체 롤백 |
| 2개 동시 매수 요청 | 직렬화, 현금 초과 사용 금지 |
| 오류를 유발한 leg 입력 | 이벤트도 롤백 |
| 원장 직접 수정·삭제 | 최종 권한 정책에서 거부 |
