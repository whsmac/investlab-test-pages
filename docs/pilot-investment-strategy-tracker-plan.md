## 1단계 잔여 구현 순서
1. 별도 소유자 제한 전략 저장 모델. 시작일/기준가격/수량/가치 고정. 원장과 별도 전략 문서; version/updated_at 동시성 보호, RLS와 계정 전환 검증. 기존 백업 및 복원 범위 검토. TEST DB 스키마 확인 후 진행.
2. 거래 ID 기반 전략 배정(부분 수량/정산금액/수수료 합계 검증). 같은 계좌에서 복수 전략; 중복 배정 및 원장 수정·삭제 후 부족 상태 차단. 전략 시작 이후 배당, 환전, 현금 이동, 분할/합병 처리 검토. 외부 입출금은 투자수익과 구분. 기존 원장 직접 덮어쓰기 금지.
3. 가상거래 전략 가져오기: 예상값과 실제 배정 분리, 사용자가 실제 시작 기준 확정. 자동 매매 실행 없음.
4. 공통 현재가 선택 기능 및 최신성 표시, 시세 갱신; 지원되지 않는 종목은 오류 표시. USD/KRW 환율 시점 검증. 공개 종가만 있을 때 실시간으로 표시 금지.
5. 기존 세금 추정 기능 재사용 검토. 연간 전체 실현손익/기본공제 중복 방지, 실제 원화 기준 세금과 추정값 구분. 수수료 및 환전 비용 분리.
6. 목표 확보량 이력 및 운용수익률/목표자산 비교, 전략 종료 시 실제 거래 기준 확보량 및 예상 대비 실제성과 기록. 종료된 전략의 배정 해제.
7. 공통 네비게이션, PC/모바일, 사용자 2명 격리, 저장 충돌/원장 수정/재로그인 확인. 기존 기능 회귀검증 후 검증된 구현 커밋을 배포 워크플로에서 지정.
## 수용 기준
- 예시 47,212 USD / TSLA 420 USD => 112주, 시작 100주·목표 120주 => 60%. 세금·비용 1,800 USD 입력 시 108주.
- 보유량 초과 및 같은 수량 중복 배정 거부, 다른 사용자 원장/전략 노출 금지.
- 시세/환율 미확인 시 계산 중단, 종가 및 실시간 명시.
- 수량/금액은 통화 명시 정수 표시 원칙(분수주 실제 수량은 명확히 구분), USD 주가 및 환율 소수점 1자리.
- 실제 시작 후 기준값 변경 금지 또는 명시적 전략 재시작. 목표/성과 이력, 종료 기준 명시.
- 배포 전 전체 회귀 검증 및 원장·기존 전략 보존.
