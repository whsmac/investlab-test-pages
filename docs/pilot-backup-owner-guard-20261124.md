2026-11-24. Review of PR #20 successor. No real account or database access.
A restore previously captured the active account only after asynchronous file reading; an intervening account change could redirect an in-flight restore. Export previously used browser storage without re-verifying the server account. Both operations now capture the starting owner and generation, require server identity confirmation, and abort on owner/generation mismatch. A detected logout/relogin invalidates an earlier operation, even if the same account logs in again. Restore still changes only that account's browser storage, preserves duplicate confirmation and no-op behavior, and does not synchronize the imported backup automatically to the server. Existing backup file format remains compatible. A manually selected file is not proof of its original owner; this guard is not an authorization boundary or a server RLS verification.
