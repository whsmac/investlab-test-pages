# TEST 개인 데이터 격리 설계 — 검토 전용

## 목적
공유 기업 데이터(6개 기업, 주가 4,938건)는 기존 TEST 테이블에서 그대로 조회한다. 개인 투자정보는 `auth.uid()`로 사용자별 분리한다.

## 신규 테이블 (미설치)
- `investlab_personal_holdings`: 계좌별 보유종목과 평균취득가
- `investlab_personal_cash`: 계좌별 USD/KRW 현금 잔고
- `investlab_personal_ledger`: 거래·배당·입출금·환전 기록
- `investlab_personal_scenarios`: 가상 거래 시나리오 JSON

## 안전 게이트
1. TEST 프로젝트 ID와 대상 스키마를 수동으로 확인한다. 운영 DB에는 적용 금지.
2. 같은 이름의 기존 테이블/정책이 있는지 사전 확인한다. SQL은 신규 테이블만 대상으로 설계되었으며 재실행 가능 마이그레이션이 아니다.
3. 2개 TEST Auth 사용자 A/B로 각자 INSERT/SELECT/UPDATE/DELETE가 가능하고 타인 행 조회·수정·삭제·삽입이 차단되는지 검증한다. anon 차단도 확인한다.
4. 트랜잭션 롤백, 정책/권한 및 인덱스 점검 후에만 UI 쓰기 기능을 별도 PR에서 고려한다.
5. 사용자별 인증 세션을 사용한다. service_role, sb_secret 키를 브라우저에 넣지 않는다.
6. 현재 개인 포트폴리오 로컬 데이터는 자동으로 이동하지 않는다. 향후 이관은 원본 백업·중복방지·사용자 승인 후 별도 단계로 한다.

## 후속 설계 보완
- 현금 잔고와 원장의 정합성: 원장 단일 원천으로 정하고 현금 잔고는 파생/검증하도록 설계 필요
- 환전 이벤트의 양 통화 금액과 수수료, 계좌 간 이체 모델 확정
- 원장 거래별 취득원가·실현손익·세금 기준 및 통화 환산 기록 확정
- 사용자별 종목관리(관심/과거) 테이블, 시나리오 JSON 스키마·크기 제한, 이력/감사 및 동시 수정 충돌 정책
- 계좌 식별자 및 계좌 소유권, user_id 변경 불가 정책 보강
- 기존 테이블과 정책이 있을 경우 수동 병합 마이그레이션 작성

**상태: 설계 초안. SQL 실행·DB 변경·배포 없음.**
