# INVESTLAB 개발 단계 운영 기준 (2026-11-13)

## 목표
1단계는 보고서 완성이 아니라 **실사용 가능한 투자관리 시스템**의 완성이다. 1단계를 사용하면서 발견한 문제와 개발 중 제안된 개선 아이디어를 축적하고, 사용 경험을 바탕으로 2단계 계획을 수립한다.

## 1단계 완료 조건 (실제 사용자 확인 필요)
- GitHub Pages + TEST Supabase 환경에서 본인 계정 로그인, 기기 간 데이터 유지 확인. Vercel 의존 제거.
- 내 포트폴리오: 계좌·보유·관심·거래 종목을 한 번만 등록하고, 보유 수량/평균 취득단가/현금 및 손익 확인.
- 통합 거래원장: 매수·매도·배당·환전·입출금의 계좌별 반영, 이중 입력 방지 및 오류 수정.
- 가상매매 시뮬레이터: 기존 포트폴리오 연동, TSLA→SOXL/TQQQ→TSLA 단계 거래, 가정가격·환율·현금·수량·추정 양도세·시나리오 저장 및 비교.
- 기업 투자분석: 6개 기업의 일별 주가, 분기 매출·CAPEX 차트 확인. 데이터가 없는 항목은 명시.
- 사용성: 숫자 천 단위 쉼표, 수량 정수, 환율 정수 표시, 모바일 5개 메뉴, 실제 브라우저 주요 흐름 점검.
- 사용자 1명부터 시작, 최대 6명 범위에서 계정별 접근 통제 확인.
- 사용자 승인 없이 DB SQL 실행, 데이터 이관, PR 병합, production 변경 금지.

## 1단계 현재 확인된 미완료/불확실 항목
- Draft PR의 GitHub Pages main 반영 여부: 미반영. 실사용 사이트는 별도 검증 필요.
- 개인 원장 DB 테이블 및 실제 저장·재접속 동작: TEST 설치/실증 미확인.
- 기업 분기 재무 데이터: 기존 확인 시 0건. 차트 실데이터 확보 필요.
- 계정 A/B 격리, 권한, 롤백 실증: 미실시.
- 브라우저 실사용 시나리오: 자동 테스트와 별개로 사용자 확인 필요.

## 개선 아이디어 기록 형식
- 발견일 / 사용 화면 / 문제 또는 아이디어 / 실제 사용 예시 / 기대 효과 / 긴급 오류 여부 / 예상 난이도 / 처리 상태
- 1단계 운영 중 기능 추가는 원칙적으로 보류하고, **데이터 손상·로그인 실패·중대한 계산 오류** 등 실사용 차단 문제를 우선 해결.
- 2단계 착수 전 후보를 중복 제거하고 사용자와 우선순위·범위를 확정.

## 개발 원칙
- 최종 보고서·증빙 기능 확장은 보류. 기존 안전장치는 유지.
- Draft PR은 병합하지 않는다. TEST Supabase 변경 및 실데이터 이관은 사용자 별도 승인 후 수행.
- 1단계 실사용 완료 판정은 자동 CI 통과만으로 하지 않는다.
