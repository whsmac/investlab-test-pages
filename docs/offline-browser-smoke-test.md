# INVESTLAB TEST — 초기잔고 브라우저 점검

이 문서는 TEST Draft 브랜치 `feature/test-navigation-20261112` 전용입니다. GitHub Pages의 `main` 주소에는 Draft 변경이 반영되지 않습니다. PR을 병합하거나 Supabase를 수정하지 마세요.

## 실행 준비

1. GitHub에서 `whsmac/investlab-test-pages` 저장소의 **Code → Download ZIP**을 선택하기 전에 브랜치가 `feature/test-navigation-20261112`인지 확인합니다. 또는 PR #1의 **Files changed**에서 브랜치를 확인합니다.
2. ZIP을 해제한 폴더에서 로컬 정적 HTTP 서버를 실행합니다. Python이 설치된 경우 `python -m http.server 8000` 또는 `python3 -m http.server 8000`을 사용합니다.
3. Chrome에서 `http://localhost:8000/test-portfolio-account-allocation.html`을 엽니다. `file://`로 직접 열면 ES module이 차단될 수 있습니다.
4. 개발자 도구의 Console에서 JavaScript 오류가 없는지 확인합니다. TEST 자료만 사용하고 실계좌 개인정보는 넣지 마세요.

## 시나리오 A — 정상 오프라인 검토

1. **고급 입력 · JSON 보기/수정 → 예시 채우기**를 누릅니다.
2. **계좌·종목 표 생성**을 누릅니다. TSLA 3주가 계좌 1의 1주, 계좌 2의 2주로 나뉘어 있는지 확인합니다.
3. 각 계좌의 소유 확인 및 종목별 실제 취득원가 확인 체크박스를 직접 확인합니다. 자동 승인되지 않아야 합니다.
4. **입력 반영 + 원장 대조 + 최종 점검**을 누릅니다.
5. 화면의 원장 대조 결과와 오프라인 최종 점검 결과를 확인합니다. `serverVerified:false`, `canMigrate:false`, `canPost:false`가 유지되어야 합니다.
6. **최종 점검 JSON 저장**을 누른 뒤 이전 최종 점검 파일로 다시 불러와 비교합니다. 변경이 없다면 신규 문제 0건이어야 합니다.

## 시나리오 B — 수량 불일치

1. 표에서 TSLA 배정수량을 1주 줄입니다.
2. 미배정 수량이 표시되는지 확인합니다.
3. 원클릭 검토를 실행해 수량 오류 안내가 나오는지 확인합니다.
4. 수량을 원복하고 다시 검토합니다.

## 시나리오 C — 소유/원가 미확인

1. 계좌 소유 또는 취득원가 확인 체크박스를 해제합니다.
2. **추가 확인 필요 항목만 보기**를 선택해 해당 행이 나타나는지 확인합니다.
3. **입력 위치로 이동** 버튼이 해당 체크박스에 초점을 맞추는지 확인합니다.
4. 원클릭 검토가 완료로 표시되지 않는지 확인합니다.

## 시나리오 D — 파일 일관성

1. 저장된 최종 점검 JSON을 텍스트 편집기로 열어 `review.status`를 다른 값으로 바꿉니다.
2. 수정된 파일을 **이전 최종 점검 파일**로 선택합니다.
3. 저장된 점검 결과와 입력값이 일치하지 않는다는 비교 실패 안내가 나타나야 합니다.

## 결과 기록

테스트 환경(Windows/macOS, Chrome 버전), 시나리오 A–D 성공/실패, Console 오류 메시지를 기록합니다. 실제 서버 인증, Supabase 데이터 쓰기, PR 병합, 운영 배포는 테스트 범위에 포함되지 않습니다.
